エラーハンドリング

構文エラーを直すだけでなく、実行はできたが結果が違うロジックエラーをログと検算で見抜く領域。

← SAS Base Programming 学習トップへ

Goal

ログから原因特定・修正・検算まで

ERROR、WARNING、NOTEの読み分け、PUTLOGによる追跡、典型的な構文・ロジックエラーの修正を扱います。

ERROR

  • 構文として成立しない、ファイルがない、BY 変数が不正など。
  • 最初の ERROR を優先して直す。

WARNING

  • 処理は続くが、結果が怪しい状態。
  • 意図しない型変換、出力上書き、文字値の切り詰めなどに注意。

NOTE

  • 自動変換、未初期化変数、欠損値生成など重要なヒントを含む。
  • 処理が完了していても、想定外の変換や件数がないか確認する。

Log Reading

ログは上から順に、最初の原因を探す

1 つの構文ミスが、後続の行に複数の ERROR を連鎖させることがあります。ログを読むときは、最後のメッセージではなく、最初に異常が出た位置を優先します。

1. ERROR の最初を見る

セミコロン欠落、引用符不一致、スペルミス、無効オプションなど、構文として実行できない原因を先に直す。

2. WARNING を読む

処理は続いても、上書き、切り詰め、形式不一致などで結果が崩れていないか確認する。

3. NOTE を捨てない

自動変換、未初期化変数、欠損値生成、入力行数や出力行数は、ロジックエラーの手がかりになる。

4. 件数で検算する

ログの obs 数、PROC FREQ、PROC MEANS、PROC PRINT(obs=) で、問題文の条件どおりに行が残っているか見る。

ログの行番号と下線から原因箇所を探す

ログには実行したコード、問題箇所を示す下線、エラーメッセージが表示されます。後続のERRORは最初の構文ミスから連鎖するため、最初の下線付近を修正してから再実行します。エラー番号や候補語は状況により異なります。

/* セミコロンがないため、次のELSEまで同じ文として読まれる */
75  if amount >= 10000 then status = "High"
76  else status = "Other";
    ----
    ERROR: IF-THEN/ELSEステートメントの構文を確認してください。

/* 修正後：THEN側の代入文をセミコロンで終了する */
data work.checked;
  set work.orders;
  if amount >= 10000 then status = "High";
  else status = "Other";
run;

WORK.ORDERSがamountだけを持つ4行の場合のログ例

NOTE: DATAステップが正常に完了しました。
NOTE: データセット WORK.CHECKED は4オブザベーション、2変数です。

表示言語や文言は実行環境により異なります。ERRORが消えただけで終わらず、出力行数と変数数も確認します。

PUTLOG

ロジックエラーを PUTLOG で追跡する

PUTLOG は DATA ステップ中の値をログに出します。全件出すと読みにくいため、条件付きで確認対象を絞ります。

特定の行だけをログへ出す — PUTLOG

基本形: if 条件 then putlog "メッセージ" 変数名=;

  • by customer_id; は顧客ごとのグループ境界を使うための宣言。
  • first.customer_id で累計を初期化し、SUM ステートメントで加算する。
  • if customer_id = "C001" then do; は、確認したい ID だけにログ出力を絞る。
  • putlog "DEBUG: " _n_= ...; は、反復回数と変数名つきの値をログに出す。
/* C001の処理中だけ変数の値をログへ出す */
data work.debug_total;
  set work.orders_by_customer;
  by customer_id;
  /* 顧客グループの先頭で累計を初期化する */
  if first.customer_id then total_amount = 0;
  total_amount + amount;

  /* 調査対象の顧客だけ、途中の値を変数名付きで出す */
  if customer_id = "C001" then do;
    putlog "DEBUG: " _n_= customer_id= order_date= amount= total_amount=;
  end;

  /* 顧客グループの最終行だけ結果へ出力する */
  if last.customer_id then output;
run;

ログ出力例

DEBUG: _N_=1 customer_id=C001 order_date=01AUG2026 amount=100 total_amount=100
DEBUG: _N_=2 customer_id=C001 order_date=03AUG2026 amount=150 total_amount=250
表示項目意味確認すること
_N_DATAステップの反復回数想定した入力行を処理しているか
customer_id現在処理中の顧客IDC001の行だけが表示されているか
total_amount顧客内の累計金額100、250の順に正しく加算されているか
覚える形

putlog _all_; は全変数を出せます。原因が見えないときの最終手段として便利ですが、ログが大きくなるため条件付きで使います。

自動変数

_N_ は DATA ステップの反復回数、_ERROR_ はその反復でエラーが発生したかを示す一時変数です。ログ確認や条件付きデバッグで役立ちます。

値を指定した形式でログへ出す — PUTLOGとformat

変数名付き: putlog 変数名= format.;

値だけ: putlog 変数名 format.;

日付の内部値を読みやすくするなど、ログだけに一時的な表示形式を指定できます。データセットに保存されたformatは変更しません。

/* 注文日をDATE9.、金額をCOMMA12.2でログへ出す */
data work.debug_format;
  set work.orders;
  putlog order_date= date9. amount= comma12.2;
run;

ログ出力例

order_date=01AUG2026 amount=1,250.00
order_date=03AUG2026 amount=12,500.00

DATE9.とCOMMA12.2で読みやすく表示されます。変更されるのはログ上の見え方だけで、保存された値やformat属性は変わりません。

その時点の全変数をログへ出す — PUTLOG _ALL_

基本形: putlog _all_;

プログラムデータベクトルにあるすべての変数名と値を出します。ログが大きくなるため、行番号やエラー状態で絞って使います。

/* 5回目のDATAステップ反復だけ全変数を確認する */
data work.debug_all;
  set work.orders;
  if _n_ = 5 then putlog _all_;
run;

ログ出力例

customer_id=C003 order_date=05AUG2026 amount=300 region=West _ERROR_=0 _N_=5
表示項目意味確認すること
各変数5回目の反復時点にPDVが持つ値想定した1行の値になっているか
_ERROR_=0現在の反復ではデータエラーなしエラーを調べる場合は1になった行がないか
_N_=55回目のDATAステップ反復条件どおり5回目だけ表示されたか

変数の表示順は、PDV内の並びによって異なります。

反復回数とエラー状態を確認する — _N_ / _ERROR_

_N_はDATAステップの反復回数、_ERROR_は現在の反復でデータエラーが起きると1になる自動変数です。通常は出力データセットへ保存されません。

/* データエラーが発生した行だけ反復回数と全変数を出す */
data work.checked_input;
  set work.imported;
  amount = input(amount_char, comma12.);
  if _error_ = 1 then putlog "DATA ERROR: " _all_;
run;

amount_char="ABC"を処理したときのログ例

NOTE: INPUT関数に無効な引数があります。
DATA ERROR: _N_=5 customer_id=C003 amount_char=ABC amount=. _ERROR_=1
表示項目意味確認すること
_N_=5エラーが起きた反復回数入力データのどの行に対応するか
amount_char=ABC変換前の文字値COMMA12.で数値として読める値か
amount=.変換できず生成された数値欠損値想定外の欠損値が出力へ残っていないか
_ERROR_=1現在の反復でデータエラーが発生エラー行だけがPUTLOGに出ているか

_N_は何行目の処理か、_ERROR_はその処理で失敗したか

入力を1行読む_N_=5
→
型変換でエラー_ERROR_=1
→
その行だけログへputlog _all_;

次の入力行へ進むと_N_は増え、_ERROR_は新しい反復用に0へ戻ります。

Output Logic

複数データセットへのOUTPUTを追跡する

DATAステップに明示的なOUTPUTが1つでもあると、ステップ末尾の暗黙出力は行われません。各OUTPUTが何回実行され、どの出力先へ書くかを数えます。

出力先を指定する — OUTPUT データセット名

基本形: if 条件 then output 出力データセット;

出力先を指定したOUTPUTは現在の行をそのデータセットだけへ書きます。出力先を省略したoutput;は、DATAステートメントに並べたすべてのデータセットへ書きます。

/* 金額に応じて各行を1つのデータセットだけへ出力する */
data work.low_sales work.high_sales work.missing_sales;
  set work.orders;
  if missing(sales) then output work.missing_sales;
  else if sales < 200000 then output work.low_sales;
  else output work.high_sales;
run;

入力値が「欠損、50,000、180,000、200,000、250,000」の場合

WORK.MISSING_SALES   1オブザベーション
WORK.LOW_SALES       2オブザベーション
WORK.HIGH_SALES      2オブザベーション
出力先意味確認すること
MISSING_SALESsalesが欠損の行欠損値が低額側へ入らず、1行だけ入ったか
LOW_SALES欠損ではなく20万円未満の行50,000と180,000の2行か
HIGH_SALES20万円以上の行境界値200,000を含む2行か

重複出力を見抜く — OUTPUTの実行回数

1行の処理中に複数のOUTPUTが実行されれば、その行は複数回書かれます。条件付き出力の後ろに無条件のoutput;があるコードは特に注意します。

/* category=Aの行はONEへ2回、TWOへ1回出力される */
data work.one work.two;
  set work.input;
  if category = "A" then output work.one;
  output;
run;

1行あたりの出力回数

/* 無条件のOUTPUTは両方の出力先へ書く */
category    WORK.ONE    WORK.TWO
A           2回         1回
A以外       1回         1回

入力が5行（Aが3行、A以外が2行）の場合
WORK.ONE    8オブザベーション
WORK.TWO    5オブザベーション

Aの3行はONEへ2回ずつ、A以外の2行はONEへ1回ずつ出るため、ONEは3×2＋2×1＝8行になります。

複数の構文・構造・ロジックエラーをまとめて直す

複数出力先へ振り分けるコードでは、出力先をすべてDATAステートメントへ書き、THEN OUTPUTを正しく組み立てます。数値欠損値は通常の数値より小さいため、欠損判定を最初に置き、ELSE IFで1行を1つの出力先だけへ振り分けます。

/* 修正前：出力先不足、THEN不足、欠損値の誤分類がある */
data work.low_amount work.high_amount;
  set work.orders;
  if amount < 1000 output work.low_amount;
  if amount >= 1000 output work.high_amount;
  if amount is missing output work.missing_amount;
run;

/* 修正後：欠損、1000未満、1000以上のどれか1つへ出力する */
data work.missing_amount work.low_amount work.high_amount;
  set work.orders;
  if missing(amount) then output work.missing_amount;
  else if amount < 1000 then output work.low_amount;
  else output work.high_amount;
run;

公式サンプルと同じSASHELP.HEARTでの確認結果

/* 変数をCHOLESTEROL、境界を200に置き換えて実行した結果 */
データセット       オブザベーション数
WORK.HIGHCHOL      3652
WORK.LOWCHOL       1405
表示項目意味確認すること
HIGHCHOLコレステロール値が200以上の行数境界値200がこちらへ入っているか
LOWCHOL欠損ではなく200未満の行数欠損値が含まれていないか
MISSCHOLコレステロール値が欠損の行数別データセットへ漏れなく振り分けられたか

Debug Patterns

PUTLOG は「いつ」「どの行で」壊れたかを絞る

ロジックエラーは、全行を眺めても見つかりません。疑わしい条件、特定 ID、グループの先頭・末尾など、原因が出そうな場面だけログに出します。

グループ境界と異常値をログへ出す

境界: if first.変数 or last.変数 then putlog ...;

異常値: if missing(変数) then putlog ...;

  • first.customer_id or last.customer_id は、グループの先頭・末尾だけをログに出す条件。
  • first.customer_id= のように末尾に = を付けると、変数名と値を一緒に出せる。
  • missing(amount) は欠損値を見つける条件。
  • 境界ログと異常値ログを分けると、累計ミスと入力値ミスを切り分けやすい。
/* グループ境界と金額の欠損行を分けてログへ出す */
data work.debug_group;
  set work.orders_by_customer;
  by customer_id;
  /* 顧客ごとの累計を作る */
  if first.customer_id then total_amount = 0;
  total_amount + amount;

  /* グループの先頭・末尾で境界フラグと累計を確認する */
  if first.customer_id or last.customer_id then
    putlog "BOUNDARY: " _n_= customer_id= first.customer_id= last.customer_id= total_amount=;

  /* 金額が欠損している行だけ入力値を確認する */
  if missing(amount) then
    putlog "MISSING AMOUNT: " _n_= customer_id= order_date= amount=;

  if last.customer_id then output;
run;

ログ出力例

BOUNDARY: _N_=1 customer_id=C001 FIRST.customer_id=1 LAST.customer_id=0 total_amount=100
BOUNDARY: _N_=2 customer_id=C001 FIRST.customer_id=0 LAST.customer_id=1 total_amount=250
BOUNDARY: _N_=3 customer_id=C002 FIRST.customer_id=1 LAST.customer_id=0 total_amount=80
MISSING AMOUNT: _N_=4 customer_id=C002 order_date=04AUG2026 amount=.
BOUNDARY: _N_=5 customer_id=C002 FIRST.customer_id=0 LAST.customer_id=1 total_amount=130
表示内容意味確認すること
BOUNDARY顧客グループの先頭または末尾C001とC002の境界でフラグが正しく立つか
MISSING AMOUNT金額が欠損している入力行入力元の4行目を修正・除外する必要があるか
total_amount顧客ごとの累計金額欠損値を加えても累計が壊れず、最終値が想定どおりか

境界を見る

  • first. / last. が期待どおりの単位で立っているか確認する。
  • BY 変数を増やしたときは、初期化する単位を見直す。

異常値を見る

  • 欠損、負の金額、想定外カテゴリなど、問題文の条件から外れる行だけ出す。
  • ログが大きくなりすぎないよう、条件付きで出力する。

Syntax

構文エラーの典型パターン

SASステートメントの基本ルール

  • DATAステップはDATA、PROCステップはPROCで始まり、通常はRUN;またはQUIT;で終了する。
  • 各ステートメントはセミコロンで終了する。改行や字下げだけでは終了しない。
  • キーワードの大文字・小文字は区別されないが、引用符内の文字値は区別される。
  • 文字定数は対応する引用符で囲み、format・informat名は通常ピリオドまで含める。
/* 1つのDATAステップと1つのPROCステップ */
data work.east_orders;
  set work.orders;
  if region = "East";
run;

proc print data=work.east_orders;
run;

入力が3行（Eastが2行、Westが1行）の場合のPROC PRINT出力例

Obs    customer_id    region    amount
 1     C001           East         100
 2     C003           East         300

エラーなく完了した後も、Eastの2行だけが残ったかを出力結果で確認します。

よくある

セミコロン欠落

次の行まで 1 つのステートメントとして読まれ、後続に連鎖エラーが出る。

よくある

引用符不一致

文字列が閉じられず、以降のコードが文字列扱いになる。

よくある

キーワードのスペルミス

formt、legnth など。SAS は補正しない。

よくある

無効なオプション

PROC やステートメントごとに使えるオプションが違う。

ログに表示されるメッセージ例

原因ログに出る例確認すること
セミコロン欠落ERROR: ステートメントの構文または順序が正しくありません。最初の下線より前の文が;で終わっているか
引用符不一致ERROR: 引用符で囲まれた文字列が正しく終了していません。開始と終了の引用符が同じ種類で対になっているか
スペルミスERROR: ステートメントを認識できません。キーワードや変数名を元データと照合したか
無効なオプションERROR: オプションを認識できません。そのPROCやステートメントで使える位置・オプションか

実際のエラー番号や文言は、コードと実行環境によって異なります。最後のメッセージではなく、最初に表示された異常から確認します。

Common Notes

NOTE を読めると、ロジックエラーに早く気づける

NOTE は「失敗」ではありませんが、結果を疑うべきサインを含みます。特に型変換、未初期化変数、欠損値生成は頻出です。

自動変換

  • 文字と数値を比較・計算したときに起きる。
  • INPUT / PUT で明示変換へ直す。

未初期化変数

  • 変数名のスペルミスや、条件分岐で代入されない経路が原因になりやすい。
  • PROC CONTENTS と PUTLOG で変数名と値を確認する。

欠損値生成

  • 無効な入力値、日付読み込み失敗、欠損を含む演算で発生する。
  • 入力データ、informat、計算式の順に確認する。

自動型変換が起きるコードを見分ける

文字変数を数値式へ入れる、または数値変数を文字式へ入れると、SASが型を自動変換する場合があります。処理が続いてもログに変換のNOTEが出るため、INPUTまたはPUTで意図を明示します。

/* 自動変換：amount_charが計算時に数値へ変換される */
total = amount_char + tax;

/* 明示変換：文字値の形式を指定して数値へ変換する */
amount = input(amount_char, comma12.);
total = amount + tax;

amount_char="1,250"、tax=125の場合

/* 自動変換したコードのログ例 */
NOTE: 文字値を数値に自動変換しました。
NOTE: 無効な数値データ amount_char='1,250' が見つかりました。
total=.

/* INPUTで明示変換した結果 */
amount=1250
total=1375
表示項目意味確認すること
自動変換のNOTESASが式に合わせて文字値を数値へ変換した意図したinformatで変換されているか
total=.自動変換に失敗し、計算結果が欠損出力に想定外の欠損値が残っていないか
amount=1250COMMA12.でカンマ付き文字列を数値化変換後の値と最終計算結果が正しいか

Logic

ロジックエラーの探し方

ロジックエラーは、構文としては正しくても、結果が問題文と違う状態です。見つけるには、途中結果を小さく検算します。

件数を確認

PROC PRINT(obs=)、ログの obs 数、PROC FREQ で意図せず行が増減していないか確認する。

型と長さを確認

PROC CONTENTS で文字 / 数値、文字長、format を確認する。文字長不足は値の切り詰めにつながる。

条件を確認

WHERE と IF、日付定数、大小比較、欠損値の扱いを確認する。

グループ境界を確認

first. / last. が意図した単位で立っているか、BY 変数とソート順を確認する。

Comprehensive Test

ログの原因を直す総合確認テスト

セミコロン不足、自動型変換、BY処理の前提不足を解消し、異常値をログへ出すコードを完成させてください。

問題 1. ログに複数のERRORが出たとき、最初に確認するものはどれですか。

問題 2. 構文エラーをすべて直したコードはどれですか。

問題 3. 顧客別累計を正しく計算し、金額の欠損行と高額行をログへ出してください。

/* BY処理の前に並べ替える */
 data=cert.orders out=work.orders_sorted;
   customer_id;
run;

data work.checked;
   work.orders_sorted;
   customer_id;
  if amount =  then flag = 1;
  if  then total = 0;
  total  amount;
  if (amount) then
     "MISSING: " _n_= customer_id= amount=;
  if amount > 100000 then
     "HIGH: " customer_id= amount=;
  if last.customer_id then output;
run;

/* 欠損、20万未満、20万以上の順で1か所へ出力する */

  set work.orders;

  else if sales < 200000 then output work.low_sales;
  else output work.high_sales;

/* INPUTで変換できなかった行だけ全変数をログへ出す */
data work.checked_input;
  set work.imported;
  amount = (amount_char, comma12.);
